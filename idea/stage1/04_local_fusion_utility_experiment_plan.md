# 方案一：学习局部融合修改的收益与代价

日期：2026-09-20。状态：首版独立实现已写入 `../local_fusion_utility/`，尚未运行训练或正式评价。

本文记录本轮推荐主方案；另一候选方案见 `05_task_separated_fusion_experiment_plan.md`。保存计划不构成启动实验或修改冻结代码的授权。

## 1. 核心意思

不只判断“哪个 peer 看起来可靠”，而是预测：在当前局部区域改变某个来源的融合贡献，最终能补回多少目标、损失多少原 TP、增加多少 FP。没有明确收益时保持原 full。

来源单独能够检出，不等于适合修改当前融合结果。主方案直接修改多尺度融合权重，不是检测端小修复模块再加 attention。

## 2. 依据与边界

- Stage-3C 固定 64 个失败候选帧、24 个成功控制帧；41 个焦点存在局部恢复动作，且各自存在无原 TP 损失、无新增 FP 的选择。
- 这些区域、有效来源与事后动作选择依赖 GT，不是可部署效果，也不是新方法性能上限。
- Fog/Rain 常涉及高分但定位不准的竞争框；修准原抑制框可以恢复目标。
- Snow 有低分问题，但部分提分后仍进入 NMS 竞争；权重干预有两个分数替换未覆盖的恢复目标。
- 无条件局部修改会误伤；同帧多个区域联合修改的收益不能由单区域收益直接相加。
- 当前证据不证明 query 是唯一根因，也不证明通信、丢包或位姿误差是根因。

证据入口：`03_stage3c_results_and_conclusions.md`、`../qa_local_intervention/`、`../qa_stage3c_offline/analyze.py`。

## 3. 实际接入路径

Stage-3 实际路径是 `stage3_runtime → EvidenceModel → CommunicationModel → 冻结 GSPR/来源骨干 → masked AttFuse → deblocks → 分类/回归头`。

- runtime 强制 `proj_first=True`，点云先投到 ego 坐标再编码。
- 三尺度通道为 64/128/256，各尺度独立融合，随后上采样拼接成 384 通道。
- 分类与回归头分别为 1×1 卷积，但读取同一份融合特征。
- Stage-3 使用全来源掩码，没有执行预算裁剪。
- 当前诊断和历史评价使用平面多边形 IoU，论文须明确为 BEV IoU，不能写成体积 3D IoU。

新模块位置：来源特征形成之后、各尺度 `deblocks` 之前。首轮冻结 GSPR、来源骨干和原检测头，在独立模块、入口、配置中实现。

## 4. 输入、输出与动作

### 输入

- 各尺度来源特征 `F_s: [N,C_s,H_s,W_s]`。
- 原来源权重 `W_s: [N,1,H_s,W_s]` 和 full 特征 `B_s: [1,C_s,H_s,W_s]`。
- 来源独立预测和 full 的分类、回归图；包括低分 anchor。
- 来源可用掩码；局部与邻近网格的特征摘要。
- 预测框中心、尺寸、朝向差异可以作输入，但不当作真实定位误差。

当前默认配置推导的三尺度大小约为 100×352、50×176、25×88；实现前以实际 checkpoint 配置核实。

### 空间区域

使用固定 BEV 决策网格，不用 GT 框。首版建议尺度 0 的 8×8 格作为区域，约 6.4m×6.4m；这是初始设计值，不是已验证最优值。推理覆盖全部网格，因此不依赖最终高分框触发。

训练采样兼顾预测活跃区域、低分区域和均匀背景，不用 GT 定位采样区域。固定网格可能切开目标，是需要评价的风险。

### 动作空间

每个区域选择：

1. KEEP_FULL：保持原权重。
2. 使用某个可用来源 j 的特征作为查询参考，在尺度 0、1 同时生成来源权重；尺度 2 保持原样。

来源 j 对来源 i 的权重为 `softmax_i(dot(F_j,s, F_i,s) / sqrt(C_s))`。随后仍对所有可用来源进行融合，并非直接替换为单个 peer 的输出。

首版使用完整切换，不引入额外强度搜索。ego 可作为来源查询参考，但其结果等同原查询时应合并重复动作。尺度 0、1 单独修改仅用于消融。

输出是修改后的多尺度融合特征和区域动作图，随后使用原检测头、原筛选和 NMS。分类与定位共享动作，不预设两者必须选择不同来源。

## 5. 训练监督

在官方训练集内生成有限数量的修改前后配对：

1. 正常前向，缓存来源特征和 full 结果。
2. 按上述非 GT 区域规则采样网格和来源。
3. 修改局部权重，重跑检测头与原后处理。
4. 训练 GT 仅用于评价修改后的完整输出：新检出 GT、原 TP 丢失、新增 FP。
5. 用共享来源评分网络预测这三项，使用一个三输出回归损失，例如归一化后的 Smooth L1。

推理效用定义为：`U = 预测恢复数 - λ_loss × 预测原TP损失数 - λ_fp × 预测新增FP数`。最佳动作未超过门槛则 KEEP_FULL。代价系数与门槛只能用验证集确定，各天气共用。

必须固定 TP/FP 匹配与新增 FP 的定义；FP 净差不能代替新增 FP。监督评价完整场景，不能只看焦点目标或同一 anchor。一个网格含多个目标时须计入全部影响。

此过程属于方法训练标签生成，不是追加 Stage-3 大规模诊断。每帧采样数、额外前向次数、缓存成本需明确计入预算。不得从 Stage-3 的 88 帧训练选择器。

训练后段可在当前选择器产生的多区域动作背景下，重估采样区域的边际收益，减少单区域训练与联合推理的差异；该步骤如采用，须固定刷新次数并计入预算。推理不枚举重放动作。

## 6. 推理与通信

- 推理只需已收到的特征、预测摘要和选择器，不需 GT 位置、GT IoU、有效 peer 标签或天气类别。
- 没有邻车或没有可靠增益时保持可用原分支。
- 首轮保留全覆盖通信，统一使用 raw/full 或已经验证的 level0_recompute，不把通信选择混入主变量。
- 从接收端已有特征计算来源预测摘要，可不增加消息字段，但增加计算；若改为发送端传框或质量图，必须计入实际字节。
- 推理成本包括 full 摘要、逐来源检测头、区域选择器和修改后的解码，不能宣称免费。
- KEEP_FULL 不是不退化保证，错误选择及跨区域 NMS 仍会造成损失。

## 7. 最小实验矩阵

| 编号 | 方法 | 核心问题 |
|---|---|---|
| M0 | 当前冻结原融合模型 | 原始参照 |
| M1 | 普通可训练局部 attention，保留同样的 full 通道 | 增加容量是否已足够 |
| M2 | 置信度加权融合＋full 保留门 | 简单来源置信度是否已足够 |
| M3 | 检测端小修复模块，预测是否修改并联合调整框与分数 | 只修检测端是否已足够 |
| M4 | 本方案 | 最终收益与误伤监督是否有独立价值 |
| M5，条件加入 | M4＋M3 | 仅在 M4 有独立收益后检验互补性 |

M2 是 Where2comm 思路的受控适配，不冒称完整复现。M3 从 full 与来源的预筛选预测生成区域：较低内部阈值、每来源 top-K 和空间分散配额；参数在验证集固定，最终评价阈值统一。不得用 GT 候选或只保留高分目标。

必要消融：

| 变体 | 保持不变 | 检验主张 |
|---|---|---|
| 用普通检测损失改善代替最终恢复/误伤监督 | 网络、动作、采样和预算 | 是否超过项目已有 gain 思路 |
| 去掉 KEEP_FULL | 其他动作与数据 | 拒绝修改是否减少误伤 |
| 尺度 0+1 改为仅 0、仅 1 | 选择器与预算尽量一致 | 双尺度联动是否必要 |

简单备选：共享来源权重＋full 保留门，只用普通检测损失训练。它作为工程备选和强基线，暂不足以独立成为论文主贡献。

## 8. 统一协议与报告

- train：官方训练集；统一 clean/模拟天气比例、强度与种子。validation 不反向传播。
- validation：固定天气生成或确定性种子；统一选轮次和阈值。Stage-3 样本单列为机制复查，不能代替独立评价。
- test：现有 Clean、OPV2V-W Fog/Rain/Snow；关闭在线天气，单一 checkpoint，不按天气选权重。
- 同初始化、来源编码器、车辆数、范围、通信模式、更新次数和数据暴露次数。额外标签生成单列计算量。
- 主要可训练方法使用相同三组种子；确定性 M0 不必机械重复。
- 报告四条件 AP30/50/70，明确 BEV IoU，沿用非全局排序协议。
- 报告新检出 GT、原 TP 丢失及比例、保留 TP 分数变化、FP 总量和新增 FP。
- 报告参数、显存、融合/总延迟、训练标签耗时和实际序列化字节；新增框、质量图及元数据分别记账。

通过标准：独立完整测试有稳定净收益，并超过普通 attention、置信度融合和检测损失收益监督；不能用天气增益掩盖 Clean 退化或明显新增 FP。只胜过 M0 不足以证明主张。

## 9. 创新边界与失败风险

本项目 `gspr_evidence/supervision.py` 已有实际检测损失改善监督。局部路由、残差保留、收益预测本身不新。潜在区别是：评价已收到信息的融合修改，并把最终候选竞争后的恢复、保留与误伤作为共同学习目标。

最可能失败：收益标签稀疏导致永远保持 full；天气分布变化导致误选；固定网格切目标；多个区域收益不可加；有限 query 操作无法恢复损坏表征；离散后处理收益难预测。

不能宣称根因已确定、天然不退化、41 个目标是部署上限，或本方案必然达到这些恢复机会。

## 11. 证据、假设与待验证结论

- 已有证据：局部权重修改能恢复部分目标，也会误伤；来源有效不等于修改有益。
- 设计假设：预测中存在可学习的收益线索；最终竞争结果监督优于普通损失收益监督。
- 待验证：独立 AP、原 TP 保留、多区域交互、跨天气稳定性及计算性价比。本文不记录任何新实验成功结论。
