# 第二版：A0B0 + 小型优先级调整网络

模式名 `residual`。不改变原有模式或 GSPR 冻结代码。

流程：A0 产生并发送量化需求 → 邻车计算 B0 分数（需求×前景置信度）→ 小网络输出有正有负的调整量 → 调整后按相同预算选块 → 原 masked AttFuse 检测。

网络输入为邻车自身的六个质量/支持统计、邻车前景置信度、收到的需求，共八通道；不读取自车完整特征、不额外发送质量图。两层 3×3 卷积（16 通道）加一层 1×1 输出，共 3505 个参数。没有加入新的需求头或融合模块。

公式：`score = request * sender_confidence + 0.1 * tanh(network_output)`。0.1 是本次预先指定的初始实验超参数，不是根据测试 AP 选出的值；它限制整个训练过程的调整幅度。分数用于排序，不再要求落在 [0,1]；不裁剪以避免人为截断梯度。加法允许低基础分区域被提升，但不保证有限幅度足以解决所有错误。

最后一层权重和偏置初始化为零，初始分数/选区与 A0B0 完全一致。第一步梯度先更新输出层，后续才传入前两层，这是零输出初始化的正常行为。只训练 correction，旧 A/B 与完整前端均冻结。

保留原检测损失和原软反向近似，不增加教师、oracle 或额外监督。硬前向和预算不变。此次只验证“规则起点加有界调整”是否改善学习，未宣称解决了软反向与排名不一致的问题。

新增诊断（训练终端以及评测 frames.jsonl）：
- `replaced_blocks_vs_a0b0`：同一帧相比规则新选入多少块。
- `replacement_fraction`：新选入块数 / 已发送块数。
- `mean_abs_score_adjustment`：所有候选区域的平均绝对调整量。

初始换块率应为零；训练后分数变化但换块率始终为零，说明没有改变实际消息。换块率大并不保证 AP 更好。最佳权重仍按 validation detection loss 选择，不保证它在 AP 上优于规则；没有自动回退成规则并把它当作学习收益。

## 运行

上传更新后的整个 gspr_communication/ 目录，不覆盖其他目录。确认 HCU 0 空闲，然后：

```bash
cd /home/cjm/OpenCOOD-main/cjmnet
bash gspr_communication/run_residual.sh
```

脚本使用已确认的 seed20260907 GSPR 联合权重，读取上一轮 `/data/cjm/datasets/logs/gspr_comm_a1b1_seed20260908_20260908_160747/experiment.yaml`，只加入 residual 模式与其两个参数。数据划分、学习率、轮数、种子、预算等保持原协议，输出全新时间戳目录。不会读取旧 A/B selector 权重。

依次执行单元测试 → 真实样本 verify → 训练 → 同 54 帧范围的评测 → 汇总。任何失败停止。新 verify 在同一份编码特征上严格检查零初始化的请求、分数和选区与 A0B0 完全相同；通信字节也严格相同。独立完整前向的检测输出使用与已有全通信检查一致的 FP32 容差（atol=rtol=2e-4），并打印最大绝对误差，避免把浮点微小差异误判成选择策略差异。还检查 correction 梯度和旧 A/B 冻结状态。训练与评测完整终端日志放外部数据盘。

旧模式的命令和 checkpoint 仍按原 README 使用。新 checkpoint 多保存 correction 字段，评测 residual 必须加载这个字段，不会静默随机初始化。

当前仍是 Clean 小样本实验。Windows 无 torch，新增张量/真实样本检查需服务器执行；之前 v1 通过的检查不代表本版已通过。
