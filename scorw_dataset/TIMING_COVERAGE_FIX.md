# D0计时距离覆盖修复

旧版预检查已清点全量原始数据，记录2044547893个点。用户提供的GENERATION_BUDGET.json只有一个停止原因：untimed_nonempty_distance_bins:[7]。配置中第7段为120–200m，三个结构计时点云没有这段的点，全数据中却存在。

原报告预计磁盘261.7GB、剩余525.3GB，加107.4GB预留后仍满足；预计并行内存10.2GB、可用1470.7GB；预计651.9 CPU小时，低于20000小时。15.35天低于60天，但由于距离计时缺失，只能作为补测前的暂估，且不含全部后续审计和GPU推理。上述数值来自旧版服务器报告，新版本需要重新测量。

修复保留三个原结构样本，按照已清点的Clean距离直方图，为漏掉的非空距离段选择路径字典序最前的可用Train PCD，再按原始索引等间距取少量光路。同一个补充PCD若覆盖多个缺失段，只读取一次。数量上限由现有光路预算和固定距离段数决定，不按天气结果挑点或反复抽样。

全部样本的PCD身份、原始点索引和雾场身份在天气计算前冻结。缺失段没有Train来源时仍然停止；读入后覆盖不足也继续停止。终端报错会直接列出reasons，预算报告增加未覆盖的实际距离范围及暂估标记。

天气模型、主seed、接收器、积分步长、全量生成规则、预期scene/帧数以及资源门槛均不变。旧P0–R3源码及结果不变。这里只改计时审计、验收测试、失败提示与运行目录版本。

新输出根为/data/cjm/datasets/scorw-fog-v1-coveragefix，新日志根为/data/cjm/datasets/logs/scorw-fog-v1-coveragefix。旧preflight目录保留，不能用新源码RESUME旧合同；新目录第一次运行使用RESUME=0。FULL总脚本包含重新检查及后续D0–D7，用户无需逐阶段启动。

新增3个服务器验收测试：补齐原三个云缺失的距离段且输入顺序不影响选取；无Train来源时仍阻断并拒绝Test输入；多个缺失段共用PCD且固定索引和采样预算不变。本地仅静态检查，不运行这些测试或真实实验。
